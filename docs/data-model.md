# Data Model

This document will capture the analytical star schema, staging contracts, and KPI data lineage.

## Planned Coverage

- `raw`, `staging`, and `analytics` table responsibilities
- Fact and dimension table definitions
- Surrogate key strategy
- Refresh and loading behavior

## Raw Schema

### `raw.orders`

Stores source order records exactly as extracted by the ETL worker.

| Column | Purpose |
| --- | --- |
| `id` | UUID primary key generated by the worker |
| `job_id` | ETL job that loaded the row |
| `source_id` | Data source that supplied the row |
| `row_number` | Source file or provider row position |
| `payload` | Original extracted row as JSONB |
| `ingested_at` | Ingestion timestamp |

## Staging Schema

### `staging.orders`

Stores validated and normalized order records from the MVP orders pipeline.

| Column | Purpose |
| --- | --- |
| `id` | UUID primary key generated by the worker |
| `job_id` | ETL job that loaded the row |
| `source_id` | Data source that supplied the row |
| `order_id` | Source order identifier |
| `order_date` | Parsed order date |
| `customer_email` | Lowercase customer email |
| `product_sku` | Product SKU |
| `product_name` | Product display name |
| `region` | Sales region |
| `quantity` | Positive integer quantity |
| `unit_price` | Non-negative unit price |
| `currency` | Uppercase currency code |
| `campaign` | Optional campaign attribution |
| `revenue` | `quantity * unit_price` |
| `loaded_at` | Staging load timestamp |

## Analytics Schema

The Phase 4 analytics model is a small sales star schema loaded from `staging.orders`.

### `analytics.dim_product`

| Column | Purpose |
| --- | --- |
| `product_key` | Surrogate product key |
| `product_sku` | Unique product SKU |
| `product_name` | Product display name |

### `analytics.dim_customer`

| Column | Purpose |
| --- | --- |
| `customer_key` | Surrogate customer key |
| `customer_email` | Unique customer email |

### `analytics.dim_region`

| Column | Purpose |
| --- | --- |
| `region_key` | Surrogate region key |
| `region_name` | Unique region name |

### `analytics.dim_campaign`

| Column | Purpose |
| --- | --- |
| `campaign_key` | Surrogate campaign key |
| `campaign_name` | Unique campaign name, using `unattributed` for empty campaign values |

### `analytics.fact_sales`

| Column | Purpose |
| --- | --- |
| `sales_key` | Surrogate fact key |
| `order_id` | Source order identifier |
| `order_date` | Sales date |
| `product_key` | Product dimension reference |
| `customer_key` | Customer dimension reference |
| `region_key` | Region dimension reference |
| `campaign_key` | Campaign dimension reference |
| `quantity` | Units sold |
| `unit_price` | Unit price |
| `revenue` | Sales revenue |
| `source_id` | Source data source |
| `job_id` | ETL job that produced the row |
| `loaded_at` | Analytics load timestamp |

### `analytics.v_dashboard_overview`

Aggregates `total_revenue`, `total_orders`, `total_customers`, and `average_order_value` from `analytics.fact_sales`.

### Power BI Views

Stable reporting views:

- `analytics.pbi_sales_overview`
- `analytics.pbi_sales_detail`
- `analytics.pbi_daily_revenue`
- `analytics.pbi_revenue_by_product`
- `analytics.pbi_revenue_by_region`
- `analytics.pbi_revenue_by_campaign`

These are the preferred external BI contract. Power BI should use these views instead of joining star schema tables manually.

## Application Schema

### `app.users`

Stores local development users for the protected frontend shell and API authentication.

| Column | Purpose |
| --- | --- |
| `id` | UUID primary key generated by the API |
| `name` | User-facing display name |
| `email` | Unique login email |
| `password_hash` | Salted scrypt password hash |
| `role` | Application role, defaulting to `ANALYST` |
| `created_at` | Creation timestamp |

### `app.data_sources`

Stores business source definitions registered through the Phase 2 source management flow.

| Column | Purpose |
| --- | --- |
| `id` | UUID primary key generated by the API |
| `name` | User-facing source name |
| `type` | One of `ECOMMERCE`, `CRM`, `MARKETING`, `SUPPORT`, or `CSV` |
| `status` | One of `DRAFT`, `CONNECTED`, `FAILED`, or `DISABLED` |
| `schedule` | Local scheduling hint such as `manual`, `daily`, or `hourly` |
| `config` | JSONB provider configuration or CSV path metadata |
| `last_connection_test_at` | Most recent connection validation timestamp |
| `last_connection_message` | Human-readable validation result |
| `created_at` | Creation timestamp |
| `updated_at` | Last update timestamp |

The API reads and writes these records through PostgreSQL.

### `app.etl_jobs`

Stores persisted ETL job executions created by the Phase 3 API orchestrator.

| Column | Purpose |
| --- | --- |
| `id` | UUID primary key generated by the API |
| `data_source_id` | Optional reference to `app.data_sources` |
| `pipeline` | Pipeline key, initially `orders` |
| `status` | One of `QUEUED`, `RUNNING`, `SUCCEEDED`, or `FAILED` |
| `processed_rows` | Number of records accepted by the run |
| `rejected_rows` | Number of records rejected during validation |
| `started_at` | Runtime start timestamp |
| `finished_at` | Runtime completion timestamp |
| `duration_ms` | Runtime duration in milliseconds |
| `error_message` | Failure reason, when applicable |
| `created_at` | Creation timestamp |

### `app.etl_job_logs`

Stores ordered stage-level job messages.

| Column | Purpose |
| --- | --- |
| `id` | UUID primary key generated by the API |
| `job_id` | Required reference to `app.etl_jobs` |
| `stage` | Pipeline stage such as `extract`, `validate`, or `load_staging` |
| `level` | One of `INFO`, `WARN`, or `ERROR` |
| `message` | Human-readable log entry |
| `metadata` | JSONB structured context for the log entry |
| `created_at` | Log timestamp |

### `app.ai_question_logs`

Stores AI analyst request audits.

| Column | Purpose |
| --- | --- |
| `id` | UUID primary key generated by the AI analyst service |
| `question` | User question text |
| `status` | One of `answered`, `blocked`, `unsupported`, or `error` |
| `intent` | Classified query registry intent |
| `sql_preview` | Read-only SQL preview for answered questions |
| `summary` | Returned analytical summary |
| `result_rows` | JSONB copy of the returned result set |
| `created_at` | Audit timestamp |
